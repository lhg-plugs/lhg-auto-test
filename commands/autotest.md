# /lhg-auto-test:autotest —— 一句话生成可执行的测试

用户输入在 `$ARGUMENTS` 中：功能描述（必填），可选类型开关 `--api`（接口测试）/ `--ui`（页面测试）/ `--unit`（单元测试）。缺省时按功能描述自动判断。

## 流程（依次加载 lhg-at-cases → lhg-at-script → lhg-at-quality 全程指导）

### 1. 澄清（最多 2 轮，不写代码）
- 功能的一句话描述是否清楚"输入→输出→谁用"？不清楚就问（一次问全）。
- 确认被测对象类型：API 接口 / 页面交互 / 纯函数逻辑。
- 确认运行环境：Python 版本 / Node 是否可用 / 要不要真实浏览器（Playwright 需用户本机安装，此处只给脚本，不强求跑）。

### 2. 设计用例（加载 lhg-at-cases）
按"正常 / 边界 / 异常"三类输出用例表，每条含：编号、用例名、前置条件、输入、预期结果、类型标签。
数量建议：小功能 6~10 条（正常 2~3、边界 2~3、异常 2~4），不贪多。
**这一步先给用户过目**——用例设计是"先审计划再写代码"，用户点头后再生成脚本。

### 3. 生成脚本（加载 lhg-at-script）
- API：`curl` 可读脚本（每条带状态码断言说明）或 pytest 风格（`pytest` + 标准库断言，无第三方依赖优先）。
- 页面：Playwright 思路的脚本（定位优先用"看得见的字"，不用脆弱 CSS），注明"本机需 `npx playwright install` 后可跑"。
- 单元：pytest 风格，正常/边界/异常各至少 1 个，带 fixture 清理。
脚本必须人类可读：变量名说人话，每条测试函数名就是用例名。

### 4. 跑审计（加载 lhg-at-quality）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/test_audit.py --target <脚本所在目录> --format text
```
blocker（如硬编码等待、无断言测试）必须修掉再交付。

### 5. 输出覆盖率 checklist 报告
按以下模板输出，存为 `docs/test-report-<功能名>.md`：

```
# 测试报告：<功能名>
- 用例总数：X（正常 a / 边界 b / 异常 c）
- 脚本：<路径>（pytest 风格 / curl / Playwright）
- 审计：blocker 0 / warning n（已处理或豁免说明）
- 覆盖率 checklist：
  [x] 正常路径全覆盖
  [x] 边界值（空/超长/临界）已覆盖
  [x] 异常路径（错误码/网络失败/权限不足）已覆盖
  [ ] 性能/并发（本次不做，原因：…）
- 未覆盖项与原因：
```

## 硬规则
- 没经过用户确认的用例表，不许直接生成脚本。
- 生成的测试里出现 `time.sleep(5)` 这类硬编码等待 → 不许交付（断言缺失同理）。
- 不许编造"测试通过"的结论：没跑过的脚本，报告里写"未执行"，不许写"通过"。
